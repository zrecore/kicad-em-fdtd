# Sourcing and verifying an antenna part's files

Goal: three files that agree with each other, with their origin recorded, so a generator script can build the part (pads, body, metal terminals) and a fit target (datasheet S11) from them. Web access from an agent is unreliable (login walls, bot blocking); where a fetch fails, say so and ask the user to download the file into `out/parts/<part>/`.

1. **Look locally first.** The user's project (KiCAD `3rd-party`, `.pretty` and `.3dshapes` folders, the symbol library, previously saved datasheets) often already holds all three. Read-only: never write into the user's project, never copy their files into this repository.
2. **Datasheet.** Search the part number plus the manufacturer; take the PDF from the manufacturer or a major distributor (Digi-Key, Mouser, Farnell/element14, Arrow), not an aggregator whose numbers may be from another revision (listings of one part disagreed by several dB). Record the revision and date. Read the conditions page: test-board size, keepout, matching parts, free space. Check that every printed impedance marker reproduces its printed dB value with `python3 .claude/skills/antenna-part-sources/s11_from_impedance.py R+jX ...`; if not, you read the wrong curve or reference.
3. **Footprint and 3D model.** Sources in rough order of reliability: the manufacturer's own download; a distributor's "CAD model / 3D model" link (often a free login); a library service (SnapEDA, Ultra Librarian, SamacSys/Component Search Engine; login, each with its own terms); KiCAD's official libraries (only for generic parts). A model from a library service is third-party: check it against the datasheet, do not trust it. Variants of one part family differ in body and keepout (record the exact suffix).
4. **Summarize what you have (read-only, no dependencies):**
   - `python3 .claude/skills/antenna-part-sources/footprint_summary.py PART.kicad_mod`: pads, courtyard, keepout zones, 3D model reference.
   - `python3 .claude/skills/antenna-part-sources/step_summary.py PART.step [--faces]`: per solid bounding box and colour; thin solids of a different colour are the metal terminals, the large one is the body. Gives terminal thickness, wrap-around length and gaps.
5. **Cross-check before building anything:** pad pitch and size against the datasheet land pattern; STEP body size against the datasheet outline; STEP origin and orientation against the footprint's pad frame (the metal terminals must sit over the pads, mirrored or not, and the model may be mirrored or rotated relative to the footprint: test both); units (mm); keepout size against the datasheet's copper-free area.
6. **Hand-off to a test.** A generator script (private if the part's board is private) writes a snapshot with the body as pseudo-components using `body.offset` and `height` for each metal piece and a dielectric block for the ceramic, and `--body REF=metal|dielectric:EPS` on the command line (see `docs/snapshot.md`). Unknowns (ceramic permittivity, loss) are fitted, labelled as fitted, and stated in the run notes. Then run `fdtd-control-check` before any fit and follow `antenna-reference-compare`.
7. **Record provenance** in `docs/PLAN.md` generically (part family, what was found, which files agreed) and the specifics (URLs, revision, file names, download date, licence) in a git-ignored note in `out/`. Vendor and third-party files are not committed; do not copy anything from the user's own design into this repository.
